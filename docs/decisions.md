# 决策与审批台账

日期：2026-09-22。用户批准的是输出完整文档，不是实现、真实账号采集、公网部署或公开发布。

## 已明确的产品方向

按员工而非单设备组织数据；允许自购多平台多账号；兼容Mac/Windows原工具；提供公网可达但需鉴权的管理面板；开源且使用与上游相同类型MIT许可；当前仅文档。

## 提议决策

| ADR | 建议 | 理由/代价 |
|---|---|---|
| 001 | 独立Collector，不先fork两个上游 | 降低UI/发布维护负担；仍需双平台适配 |
| 002 | 四账本分离 | 防止购买、额度、token、时间混成虚假精确统计 |
| 003 | 不集中AI凭据、不做强制网关 | 保留员工原登录；不能保证全部渠道覆盖 |
| 004 | 单组织自托管优先 | 简化运营与隔离边界；暂不做公共SaaS |
| 005 | Go服务端/Collector、React TS、PostgreSQL | 跨平台与运维一致；依赖版本和UI壳待验证 |
| 006 | 先Codex/Claude、再逐项兼容 | 可验证性优先；不追求上游供应商数量对等 |
| 007 | 日汇总修订与来源范围显式建模 | 避免累加快照；无事件ID时不能自动精确跨机去重 |
| 008 | 首版无活动时长/凭证附件审批 | 缩小隐私与安全面；后期单独授权验收 |

## 主要风险

上游字段变化用契约测试阻断；个人账号历史不可归属时显示未知；无全渠道数据不宣称全账号消费；员工可改日志不宣称可信审计计量；费用无票据/供应商依据不宣称真实账单核验；活动与工时混淆用功能边界和文案阻断；公网数据风险用鉴权和最小数据控制但不能宣称零风险。
