# v0.1.0 产品需求文档

项目：TokenLedger。日期：2026-09-22。负责人：@wlzh。状态：评审草案。

本文仅定义做什么、为什么与验收。界面见 [design.md](design.md)，技术见 [dev.md](dev.md)，阶段见 [plan.md](plan.md)。

## 1. 背景与目标

允许员工自购多家 AI 服务的公司，缺少按员工汇总订阅费用与授权用量的工具。新产品提供员工可见、可选择、可撤销的上报方式，让管理者形成续费、预算和使用支持的依据。

首版成功指标是数据归属明确、缺失可见、重复不累计、隐私边界可验证，而不是覆盖最多供应商。

## 2. 用户角色

| 角色 | 主要任务 |
|---|---|
| 组织所有者 Owner | 邀请成员、设置组织策略、管理权限与保留规则 |
| 管理员 Admin | 看组织内授权统计、维护订阅记录、处理数据异常 |
| 员工 Member | 绑定设备、选择账号、申报订阅、查看自己数据、暂停上报 |
| 财务 Finance | 后续版本按授权查看费用和凭证，不默认查看活动时间 |

首版交付 Owner、Admin、Member。Finance 为后期预留，不在首版界面提供未实现角色。

## 3. 首版需求与验收

P0 是发布阻断项；P1 需在文档确认时决定纳入；P2 是后续能力。

| ID | 需求与用户故事 | 优先级 | 可观察验收 |
|---|---|---|---|
| R01 | 管理者邀请员工加入组织，不靠填写邮箱冒充他人 | P0 | 邀请有到期时间且不可重复接受；未邀请者无法访问 |
| R02 | 员工可登记多台设备，并知道设备何时上报 | P0 | Mac/Windows 显示独立状态；撤销设备后新上报被拒绝 |
| R03 | 员工自主选择要上报的服务账号 | P0 | 未勾选账号不出现在上传预览或服务器；新增账号默认不授权 |
| R04 | 员工可以查看上传字段和目的地 | P0 | 发送前预览展示与实际发送同一份脱敏数据 |
| R05 | 员工可暂停/恢复、手动同步、解绑 | P0 | 暂停后不再采集和自动传输；恢复默认不回填暂停期间 |
| R06 | 管理者查看每位员工订阅了哪些产品 | P0 | 多产品多账号独立展示；免费账号不自动认定付费 |
| R07 | 公司登记购买/支付与公司承担金额 | P0 | 币种、周期、付款方式、申报状态明确；充值与消费不相加 |
| R08 | 支持的数据源提供额度与日级 token | P0 | 实测、估算、缺失、部分覆盖明确区分；不能反推 token |
| R09 | 同一员工多个设备/账号不会重复计量 | P0 | 重传结果不增加；重叠但无法去重的来源显示冲突 |
| R10 | 账号切换不会认领错误历史 | P0 | 未证明账号归属的历史保持未归属，不转给新登录账号 |
| R11 | 管理者和员工分别访问授权页面 | P0 | 员工不可读取其他员工数据；未登录不可查看组织统计 |
| R12 | 管理者能判断报告缺了什么 | P0 | 展示数据新鲜度、断档、未支持字段和统计范围 |
| R13 | 员工可看到自己的历史和购买申报 | P0 | 与管理员对该员工同口径数据一致；其他员工不可见 |
| R14 | 管理者导出报告 | P1 | 导出带口径、币种、时间区间、覆盖、生成时间和估算标签 |
| R15 | 按模型细分用量 | P1 | 来源支持才显示；未知模型保留原分类，不猜测名称 |
| R16 | 记录使用天数与最近活动 | P1 | 以实际事件而非采集心跳判断；无事件时不可宣称未使用 |
| R17 | 时长估算、通知、凭证审批 | P2 | 后续独立验收，不首版承诺 |

建议首版纳入 R14-R16 的可支持部分；具体供应商精度以验证矩阵为准。所有 P0 必须通过，不以降级掩盖归属、安全或会计口径错误。

## 4. 主流程

管理员配置组织并发邀请；员工接受邀请，阅读告知，绑定设备；在采集预览中选择账号与数据范围；系统上报允许的统计；员工登记订阅或管理员补录公司直付；管理者按人查看费用与用量；有缺失时先处理数据健康，再做续费判断。

## 5. 范围内边界

- 同一员工可有多家平台、同平台多个账号和多台设备。
- 员工个人 AI 邮箱可以不同于公司身份邮箱。
- 公司采购的共享组织额度不能伪装为该员工个人专属额度。
- token 总量是采集覆盖内可证明的用量，不自动覆盖手机、网页或云端任务。
- 员工暂停上报可见为“暂停”，不得显示为“没有工作”。
- 无官方支付来源时费用是申报记录，不标为已核验发票。
- 注册一个产品与购买多个底层模型不是同一个概念。

## 6. 明确不做

不收供应商密码/密钥，不共享账号池，不自动购买或取消套餐，不远程操作员工电脑，不读取提示词或代码，不截屏或键盘监控，不生成员工绩效评分，不保证日志防篡改，不把使用时长作为劳动工时。

首版无公共多租户 SaaS、无企业 SSO、无附件上传、无自动 OCR 账单识别、无自动供应商登录。没有经过验证的平台只提供手工登记，不能标成自动采集支持。

## 7. 非功能与成功标准

| 类别 | 目标，均待实测 |
|---|---|
| 正确性 | 相同批次提交 100 次，计量结果与提交一次相同 |
| 归属 | 跨员工、跨账号、跨组织错误归属测试全部阻断 |
| 隐私 | 凭据、内容、路径等禁止字段在上传、日志和导出均不可出现 |
| 可用性 | 员工离线不丢已确认入队且未超保留限制的数据；丢弃有计数与提示 |
| 更新及时性 | 在线正常采集下，建议每 5 分钟更新；允许上游缓存延迟并标注 |
| 界面 | 主要管理流程桌面可用，手机可查摘要，关键状态不只依赖颜色 |
| 性能 | 首屏摘要服务端 p95 小于 1 秒、页面交互目标小于 2 秒，需指定测试环境 |
| 恢复 | 可演练恢复组织、绑定、授权、购买记录与报告 |
| 可维护 | 上游字段变化不静默产生错误统计；不兼容有明确提示 |

## 8. 试点与验收方式

先使用合成样本验证重复、缺失、账号切换和删除；获授权后用至少一台 Mac、一台 Windows，覆盖一个员工两设备与两员工隔离。目标供应商先验证 Codex、Claude；Cursor 在两系统分别记录结果，不以一端成功代替另一端。

任何真实账号验证需事先授权。现阶段没有完成这些试点，没有数据准确率或费用节省率的结果。

## 9. 依赖与待确认

项目负责人为 @wlzh；仍需确认试点规模、订阅采购方式、组织时区、公司承担费用口径、员工告知流程和数据保留策略。当前默认建议为公司自托管、员工可暂停、先记录后人工判断，不强制接管员工购买流程。

产品评审通过不等于技术可行性验证完成；发现来源无法达到精度时，缩小已支持指标并修订 PRD，不能用推测补齐。
