# v0.1.0 技术设计

状态：技术提案，待批准。无现有运行代码、依赖或数据库可迁移。技术基础来自已审阅上游源码，证据见 [upstream-audit.md](../../upstream-audit.md)。

## 1. 选型

| 层 | 建议 | 理由/限制 |
|---|---|---|
| Collector | Go，用户级后台进程，轻量本地设置界面 | 跨平台发布；系统凭据库/权限需分别验证 |
| Server | Go，模块化单体 | 与Agent共享契约，首版无需多服务 |
| Web | React + TypeScript | 复杂过滤、员工与管理视图共享组件 |
| 存储 | PostgreSQL | 事务、幂等唯一性、修订与权限隔离 |
| Agent队列 | 加密持久队列，密钥存系统凭据库 | 具体库待安全评审，不自创密码算法 |
| 部署 | Docker Compose + HTTPS反向代理 | 可自托管，前端静态资源同源提供 |

版本在实施前确认并锁定；本文件不虚构已经安装的依赖或稳定性结果。不为首版引入Kubernetes、消息队列集群或ClickHouse。

## 2. 模块职责

collector/discovery：检测上游可执行文件与版本，避免运行系统中任意同名恶意程序。

collector/adapters：Mac Swift CLI与Windows Rust CLI两个独立适配器；识别来源输出而非使用一份宽松JSON映射。

collector/normalizer：将已验证字段投影到标准契约，处理时间、单位、token语义；不解析提示词。

collector/consent：本地范围选择与服务器已批准授权对照；无法隔离范围时拒绝采集。

collector/outbox：批次ID、加密队列、退避、ACK、过期与断档记录。

server/auth：成员、角色、浏览器会话、设备配对、撤销。

server/ingest：数据验证、授权重检、幂等事务、原始禁止字段拒收。

server/ledger：订阅、购买、付款关联、币种、后期审批。

server/reporting：按固定口径生成可重算视图，独立保留现金/消费/估算。

server/governance：审计、保留、删除、导出与恢复墓碑。

## 4. 采集数据流

调度器触发 -> 检查当前授权 -> 使用批准的适配器执行只读CLI -> 限时/限长读取 -> 标准化 -> 白名单拒绝/投影 -> 本地预览同源对象 -> 加密outbox -> HTTPS上传 -> 服务端原子接受 -> ACK后删除已传队列项。

上游提供只读回环快照时可替换CLI读取，不暴露回环接口到公网。每台机器每来源只有一个采集协调器，避免UI、CLI和hook并发反复触发供应商请求。

首次建议周期5分钟+随机抖动，成本扫描遵守上游缓存与限流，不因管理者刷新页面而触发员工API。钩子仅触发“可刷新”信号并受同一调度器限流。

员工账号历史只有不含混的来源标识可自动绑定；未归属日志需单独范围授权，后续认领保留证据类别。

## 5. 接口影响清单

本项目是新建系统，无现有业务接口需修改。

| 接口面 | 变化 | 兼容策略 |
|---|---|---|
| 上游usage/cost JSON | 只读消费，不修改上游 | 平台+来源+版本专属解析器 |
| 上游hook | 可选本地触发，需员工允许 | 不依赖精细token或全量事件 |
| 上游serve | 可选仅回环访问 | 验证Host与权限，不能复用作公网后台 |
| Agent -> Server | 新建ingest/1 | 严格版本、幂等、范围授权 |
| Browser -> Server | 新建管理API | 服务端权限，Cookie与CSRF |
| 数据库 | 新建逻辑实体 | 实施时独立SQL迁移并审查 |

详细路径、样例和错误见 [API契约](../../api-contract.md)。

## 6. 聚合与一致性

原子事务先检查设备/授权和批次摘要，再对逻辑源范围执行revision更新。生成报告用一致读取截止时间，不把部分写入的数据暴露为完整报告。

日聚合修订可降低或提高数值，降低不自动解释成退款，保留来源修订。禁止以最新30天累计差分代替逐日事件；窗口移动带来的下降不是负消费。

不同源范围独立保留；选择主源时记录依据和生效期。缺稳定事件ID的镜像日志不自动合并，统计总览提示未合并来源。删除和归属修正后重算相关聚合，不手工编辑报表数字。

## 7. 权限实现策略

所有API从服务端身份上下文得出组织与成员。数据库查询显式organization_id过滤并配隔离测试；RLS可作为防御层，不替代业务授权。

首版采用成熟库实现验证过的邮箱邀请/登录流程和管理员MFA。公开注册默认关闭；密码采用成熟安全哈希，恢复凭据以摘要存储；不自写认证协议。具体身份库/邮件服务在实现阶段评审。SSO后置，但架构保留独立身份提供者接口。

Collector无需管理员系统权限，不以root/SYSTEM读取所有用户配置。设备token不得读取公司报表。员工暂停/撤销不需要管理者批准。

## 8. 可观测性与运行

系统日志只存request_id、粗粒度状态、批次数和延迟，不带上游stdout、请求体、邮箱或本机路径。运维指标仅服务健康与队列积压，员工模型信息不进第三方遥测。

后端任务首版使用数据库协调的有界任务，单独处理导出、保留删除与聚合重算；任务可恢复、幂等、具有执行超时。没有独立消息队列是简化选型，不允许无限内存排队。

## 9. 范围与精度的失败策略

字段变化、账号无法隔离、凭据无法访问、来源时间未知时，阻断受影响指标并展示原因，不影响其他健康来源。source_supported与metric_supported分开表示。

Linux、WSL、浏览器、手机和远程SSH不自动算入首版支持。WSL若接入需独立桥接并获授权；不尝试绕过凭据保护。

## 10. 后续扩展点

细粒度事件导出不足时，优先向上游提出路径无关、账号/来源可归属的只读标准导出建议。没有明确授权不创建上游PR。

确需本地只读日志适配器时，不把它混入通用CLI解析，单独定义数据读取范围、隐私审查与测试。独立工具发行优先于维护两个桌面Fork。
