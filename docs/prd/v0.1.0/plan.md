# v0.1.0 实施计划草案

状态：未排期、未授权实现。本计划是依赖顺序和工作量讨论，不构成上线时间承诺。项目负责人及维护者：@wlzh；各实施角色由其协调，部署公司的运营职责仍由各公司承担。

## 1. 交付门

| 门 | 需要确认 | 未通过时 |
|---|---|---|
| G0 产品确认 | PRD、员工可暂停、首版范围与费用口径 | 不采集真实数据、不实现 |
| G1 技术确认 | dev、协议、安全与隐私边界 | 不进入数据验证开发 |
| G2 数据可行性 | 两端实机、样本一致、归属与来源范围 | 缩小支持矩阵/重审方案 |
| G3 MVP验收 | P0全部通过，P1支持范围公开 | 不邀请正式用户 |
| G4 试点验收 | 员工告知、删除/恢复、运行成本与稳定性 | 不公开生产发布 |
| G5 发布审核 | 许可证、签名、隐私/安全联系人、安装与升级 | 不发布正式安装包 |

用户授权本轮输出完整文档，不替代上述门的确认。建议先G0，再G1，不一次性把所有后续假设视为批准。

## 3. 阶段B必须回答

- 原工具已安装版本能否通过无交互方式输出需要字段。
- 同账号多设备、同平台多账号的历史能否归属。
- 源汇总的缓存、时间范围和更新延迟是否可解释。
- CLI与GUI显示差异是否来自缓存/口径而非错误。
- Windows原生与WSL是否存在未纳入数据范围。
- 未授权个人账号是否会被成本汇总混入。

任何一项不通过，都记录限制；不得以“多数情况看起来正常”代替Gate。

## 4. 版本路线

`v0.1`：基础上报、员工/设备/账号、额度与可支持日汇总、订阅购买登记、数据健康与导出。

`v0.2`：证据文件和审批、更多模型细分、可解释时间估算、预算与续费提醒。

`v1.0`：扩展兼容、成熟组织治理与长期维护。签名正式安装包、可靠备份恢复和必要运维文档是任何正式发布的前提，不能推迟到v1.0才落实。

Linux、官方组织对账、网关接入、SSO、公共SaaS作为独立提案，不默认塞入首版。

## 5. 风险与负责人类型

| 风险 | 影响 | 应对与责任 |
|---|---|---|
| 上游接口变化 | 指标不可用/错误 | 适配负责人维护契约与冻结版本 |
| 日志历史归属不明 | 账号错误统计 | 产品+数据负责人保留未归属，不猜测 |
| 费用口径误解 | 采购决策错误 | 产品+财务审核金额标签与计算样例 |
| 员工隐私争议 | 信任和试点失败 | 运营负责人先告知并限定范围 |
| 安装权限与杀软 | 无法部署 | 客户端负责人实机测试与签名 |
| SaaS范围膨胀 | 进度失控 | 单公司自托管先验收 |
| 个人数据可修改 | 不能严谨审计 | 明确辅助管理定位，不做虚假防篡改承诺 |
| 真实数据进入公开issue | 泄露 | 维护者提供安全反馈渠道和脱敏流程 |

## 6. 验收记录与变更

每个工作包输出实际负责人、开始/完成日、测试证据、未解决项。需求变化要回到PRD/决策台账，技术变化回到dev/ADR，不把设计细节塞进进度表。

重大能力降低、采集范围扩大、保留时间改变都需重新评审并告知试点员工。未批准的计划保持草案，不用勾选已完成表示仅“文档写好了”。
