# 自托管与运行设计

状态：拟议运维手册。尚无镜像、Compose文件或可执行安装命令，不能据此宣称可部署。

## 拓扑与前置门

员工Collector -> 公网HTTPS反向代理 -> 单组织应用 -> 私网PostgreSQL。只公开443；数据库、本地上游serve、管理调试端口不公开。80仅在所选证书方案确有需要时开放挑战/跳转。员工电脑无需入站端口。

上线前确定域名/DNS、TLS自动续期、负责人、身份验证方案、管理员MFA、员工告知、备份存储、恢复窗口、服务端及客户端兼容基线。建议从公司自托管单组织开始；不在首版承诺公共多租户SaaS。

## 引导与配置

初始Owner使用部署主机一次性引导秘密，首次登录后失效，禁止镜像内默认账号密码。关闭公开注册；邀请只能由授权角色发起。秘密从受保护配置注入，不能写入Git或示例文件。数据库使用最小权限应用角色，迁移角色分离。

组织时区、报告币种和保留期限首次配置明确展示。改变组织时区不重写来源日桶；汇率只作用于展示/报告，保留原币金额和采用日期。不得把不同币种直接相加。

## 容量与可观测性

试点参考环境：2vCPU/4GiB、SSD、100名成员、每人2设备、每设备3来源。每5分钟每来源一个观察是每日172800条观察；它不是172800笔消费。实际日汇总修订、心跳合并、成本扫描较慢都会改变入库量，应按实现压测测算存储。

监控接入延迟、拒绝/冲突率、采集新鲜度、队列断档、数据库空间、备份年龄和证书到期；不记录原始DTO或秘密。建议应用日志14天、代理元数据7天作为额外待审批默认，必须在部署隐私说明披露。存储不足不以删除未到期财务记录静默自救。

## 备份与恢复

建议每日加密备份，滚动30天，备份密钥独立保护；目标RPO24小时、RTO4小时仅为待验证目标。恢复演练应覆盖成员、授权、撤销、费用、报告、审计和删除墓碑。

恢复到隔离环境后先重放备份之后的撤销/删除记录，再开放接入。灾难恢复不能使已撤销设备重新有效；如果无法可靠重建吊销状态，默认全部设备重新配对。禁止把生产个人数据复制到开发环境测试。

## 升级与回滚

升级前核对支持矩阵、数据库变更兼容性、完整备份和回滚条件。迁移失败停止启动，不跳过错误；未来迁移采用扩展/迁移/收缩策略。数据库不可逆变化不能仅回滚镜像，应使用经过演练的恢复方案。

客户端与服务器分开发布，声明协议范围；不兼容时停止新上传且保留本地限期队列并提示。服务器不能下发shell或任意二进制升级命令。

## 故障处置

401/403检查设备撤销和授权，不要求员工提交AI密钥；429遵守退避；来源登录失效由员工在原工具处理；上游JSON变化停用相应适配器；其他来源继续工作。报告展示最后成功时间、来源时间与断档，不把旧值包装为实时。

疑似泄露时限制入口、吊销设备/会话、保护最小必要审计证据、通知负责人，并按适用政策处理通知。恢复后核实访问权限与数据完整性，不能仅“重启解决”。
