# 开源与发布治理

当前是公开文档草案，未发布软件。项目名 TokenLedger，负责人和维护者 @wlzh，公开仓库为 wlzh/TokenLedger。

## 许可证策略

本项目采用MIT，与两个参考上游当前许可证类型相同。独立调用已安装CLI不等于把其源码并入本仓库；若后续复制、修改、捆绑代码或二进制，必须盘点实际分发内容并随分发保留对应版权和许可。

MIT不授予上游商标、背书、供应商账户共享或绕过接口限制的权利。品牌用“兼容/适配”，不称官方团队版。依赖、字体、图标、安装器分别核验许可证。实际供应商访问方式需单独审查其允许范围，不能从MIT推导。

## 仓库材料

根目录中英文README、LICENSE、THIRD_PARTY_NOTICES、PRIVACY、SECURITY、CONTRIBUTING、CODE_OF_CONDUCT、SUPPORT、CHANGELOG应随版本同步。README明确支持范围、精度边界、隐私流向、签名验证与卸载；不使用员工真实数据演示。

维护者为 [@wlzh](https://github.com/wlzh)，仓库为 [wlzh/TokenLedger](https://github.com/wlzh/TokenLedger)。公开软件试点前落实漏洞私密渠道、社区举报渠道、签名及域名。贡献采用常规PR审查；是否引入DCO/CLA须单独决策，不在文档阶段虚构已有签署流程。

## 发布要求

版本化服务端、Collector、协议和适配器；每个发布说明最低服务端/客户端协议、OS/架构、上游已测版本、迁移/回滚、已知不支持项。文档版本不冒充应用v0.1.0。

macOS正式分发完成适当签名和公证；Windows正式分发提供可信签名方案。不指导用户关闭Gatekeeper/SmartScreen来掩盖签名问题。Checksums用于完整性检查，不替代签名与来源验证。

CI未来执行测试、依赖漏洞检查、秘密扫描、许可清单、SBOM、可追溯构建和制品签名。更新清单与制品验证独立于业务服务器；员工能看到版本和变更，更新不静默扩大采集权限。

## 维护流程

兼容性问题先补fixture再改适配器；字段语义改变需更新指标文档和数据迁移策略。旧报告保留当时口径版本，不按最新价格静默重算成另一笔“实际消费”。上游升级不直接触发全员升级，先灰度。

安全修复由明确维护人负责并约定支持版本及响应目标。尚无团队时不得承诺7×24或固定SLA。弃用来源提前说明迁移、导出与停止采集方式。
