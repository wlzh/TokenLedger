# 兼容矩阵与支持声明

当前所有自动采集均为“源码观察/待验证”，没有 runtimeVerified 项。手工订阅登记是拟议产品能力，也未实现。

## 候选能力

| 来源 | macOS 候选能力 | Windows 候选能力 | 首版处理 |
|---|---|---|---|
| Codex | 账号额度、本机日志 token/估算成本 | 账号额度、本机日志 token/估算成本 | 优先验证，分开适配 |
| Claude | 账号额度、本机日志 token/估算成本 | 账号额度、本机日志 token/估算成本 | 优先验证，历史归属独立判断 |
| Cursor | 存在 web 成本与覆盖相关结构 | 不承诺与 Mac 成本接口对等 | 逐端验证；失败保留手工购买记录 |
| Antigravity | 存在按价格表估算路径 | token 能力与美元金额缺失需分开处理 | 非首版必达项；未知价格不填0 |
| 其他上游供应商 | 各自 usage 支持不等于支持 token | 各自实现不同 | 默认未支持自动计量 |
| 任意自购产品 | 员工申报 | 员工申报 | 不伪装为自动核验 |

详细源码基线见 [审计](upstream-audit.md)。这里没有承诺网页、手机、云任务或全部模型的完整覆盖。

## 能力注册项

每个 `platform + upstream version + provider + source kind` 单独记录：二进制来源和摘要、测试OS、入口、JSON契约、账号范围、指标单位、计数是否累计、缓存是否包含于input、时区、覆盖窗口、价格来源、授权最小粒度、已知缺失、测试日期、fixture摘要和维护负责人。

证据分级：`observed` 静态源码；`fixtureVerified` 合成/授权脱敏样本验证；`runtimeVerified` 指定实机及版本验证。仅最后一级可在发布支持表标“已测试”，仍需注明覆盖范围。未安装、需登录、不支持、临时失败是不同状态。

## 平台验证计划

macOS Intel/Apple Silicon、Windows x64/ARM64分别判断。不能把交叉编译成功当实机通过。首版优先实际试点可获得的架构，未测试组合不发正式支持声明；最低OS与上游最低要求在实现前锁定。

原工具更新后先检查契约；未知版本不盲解析，保留旧值并显示过期/不兼容。兼容版本范围只能从测试建立，不写“所有最新版”。升级回归须涵盖账号切换、全账号输出、历史扫描、null、错误响应和敏感字段。

发布支持矩阵是版本产物，不能让主分支文档覆盖历史发布的真实支持范围。
